# EC2 列表健康状态修复

## 范围与已确认问题

用户授权修复、打包并更新本机应用。当前本机预览为 `0.3.1 (13)`；目标为 `arm64` 本机预览 `0.3.1 (14)`，保留旧版备份与应用配置。只使用本地模拟请求验收，不调用真实 AWS、不推送、不发布或修改更新源；不是 Goal。

此前离线复现确认：批量健康读取失败会被吞掉，列表保留实例但健康字典为空；点击详情单实例查询成功后回填，形成「未点击灰色、点击后变绿」。正常批量成功时无需选择实例即可显示状态。真实 AWS 请求失败或缺项的具体原因未证实，不能将 `running` 推断为健康检查通过。

## 实施决策与分工

- H1：健康服务、模型、EC2 ViewModel 与回归测试。列表使用当前 Profile／Region 的状态分页，不混用显式 ID 与 MaxResults；仅接纳当前实例列表结果，对仍缺项的 ID 按每批最多 100 个进行一轮补查，保留已成功数据。所有页循环和补查有界；错误脱敏、取消传播，刷新和范围变化使旧响应失效。保留详情精确单实例读取，结果可清除对应错误。
- H2：列表、双语词条、设计与文档。加载、通过、需关注、读取失败、不适用分别表达；仅明确不适用时显示灰色横杠。读取失败在行提示和列表底部明确原因与刷新重试说明；「需要关注」包含未读实例，避免将未知状态当作正常。
- H3：独立只读审查源改动及交付产物，记录安装前旧版完整指纹。主 Agent 统一测试、提交固定源码、隔离 Release 构建、核验 App／ZIP 后正常退出旧版，同卷原子备份并替换安装，再打开检查原生启动和可见窗口。验证 App、ZIP 和安装副本一致，备份与原安装一致；不冒充真实 AWS 验收。
