# AWS Platform 0.4.1 发布记录

## 授权与范围

用户明确授权推送当前改动并发布新版 Release。发布版本为 `0.4.1 (18)`，包含 `7a65d9a` 的当前模块首次加载与 `b3879f5` 的五项性能改进。保留旧 Release、既有更新公钥、历史 Feed 和本机安装，不调用真实 AWS，不变更云端资源。

## 发布顺序与验收

1. 同步脚本默认版本、对应测试和发布状态；40 项离线脚本测试、项目 release 五项门禁与源码秘密扫描通过后，固定打包源提交并推送 GitHub main，匿名读回确认源提交和公开状态。
2. 从固定提交创建独立源码 checkout，先执行 `swift package --force-resolved-versions resolve`，核对锁文件哈希和全部 pin，为许可证收集准备默认 checkout；完整许可证预检通过后，逐架构生成 Apple Silicon／Intel 的 Release App、ZIP 和 DMG。构建使用新的 SwiftPM scratch，Sparkle 与签名工具仅从固定官方归档校验通过的私有暂存消费。
3. Developer ID／Hardened Runtime／安全时间戳、公证 Accepted、票据与 Gatekeeper 全部通过；验证 App／ZIP／只读 DMG 内容一致、主程序和兼容库架构、macOS 13 最低版本、双语资源和完整许可。ARM 使用空 AWS 配置与隔离偏好启动，不替换用户安装。
4. 独立验收通过后，创建指向相同源提交的草稿 Release，上传两架构 ZIP／DMG 和汇总 SHA256SUMS，共五附件；确认远端摘要后公开为 Latest，再匿名下载全部附件核对字节数与 SHA-256。
5. 使用公开附件生成两份候选 Feed，保持版本／build 单调递增与历史项完整，归档和完整 Feed 均使用现有 Ed25519 密钥签名并独立公钥验签。审查后提交／推送 Feed 与下载入口，回读应用实际 HTTPS 地址验证线上签名和归档引用。

## 职责与证据

- 主 Agent 负责版本准备整合、提交／推送、正式打包、公证、上传／公开 Release、Feed 生成与发布。
- release-verifier 独立核验源码、产物与公开状态，只写任务临时验收证据，不执行发布变更。
- 过程证据放在 `.tmp/release-0.4.1/`，正式产物放在 `dist/AWSPlatform-0.4.1-{arm64,x86_64}/`。
- 发布成功不代表完整应用内下载／安装／重启链路、真实 AWS、Intel 或 macOS 13 实机验收；这些范围单独记录。
