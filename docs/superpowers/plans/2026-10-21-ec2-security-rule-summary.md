# EC2 实例安全规则汇总与本机预览

## 目标与边界

将实例安全页从每个 SG 各自展示规则，改为入站、出站两个汇总表。每行保留协议、端口、来源／目标、所属 SG 名称与 ID、描述；跨 SG 的相同规则不去重，保留现有安全组元数据、空状态和按需加载／失败重试行为。标题显示各方向规则总数。

只改变现有已读取数据的呈现，不变更 AWS 查询、权限、凭据、Profile／Region 范围或其他资源页面。本轮不处理此前调研发现的网卡组汇总风险，不执行真实 AWS 查询，不推送或发布 Release。

## 实现决策

- `EC2SecurityRuleSummary` 从 `[EC2SecurityGroupModel]` 生成 `inbound`／`outbound` 两组 `EC2SecurityRuleSummaryRow`，保留规则顺序与重复项。行包含 `groupId`、`groupName`、`rule`；ID 必须区分不同 SG 和同组重复规则，不使用随机 UUID。
- `EC2SecurityRulesView(groups:)` 消费该汇总模型，分开显示元数据与两个汇总表。使用 `DESIGN.md` 已定义列宽、语义样式和横向滚动，保留一个外层纵向滚动区，字段可选择复制。
- `EC2DetailView.securityTab` 继续负责元数据与安全分组的加载／错误状态，成功后消费新组件；移除本次替代的逐 SG 规则视图代码。
- 本机预览版本 `0.4.1 (19)`；发布脚本默认及线上 `0.4.1 (18)` 保持原样。固定源码提交后从隔离快照执行 ARM Release 打包，使用脚本现有受信任 Sparkle 暂存与本地 ad-hoc 签名，不上传 Apple 或 GitHub。

## 分工

- UI 实现：拥有新汇总模型、新规则组件、`EC2DetailView.swift` 及必要双语资源。禁止修改 AWS 服务、测试、设计规范和发布脚本。
- 离线验收：拥有新增汇总行为／原生渲染测试文件，覆盖多 SG、双向、重复规则、无名称、空规则和长字段，中英文／深浅色及 480 pt 窄详情。禁止修改生产源码和运行 SwiftPM；主线统一构建测试。
- 测试夹具排查：debugger 仅维护新增原生渲染测试，获准串行执行同一组 7 项定向测试；不得改生产源码、访问真实 AWS 或修改系统辅助功能权限。离屏 SwiftUI 静态标签未暴露完整 AX 子树时，使用本地 Vision 读取实际位图，完整可选择字段继续精确检查 AX。微小 `0` 字形的 OCR 不可靠，零数量由模型精确断言并人工核对原生截图，不将字母 `o` 视为数字。
- 主线：设计规范、实现整合、统一验证、文档、本地提交、固定源码打包、旧版备份与本机安装／启动。
- release-verifier：只读核对源码／产物／备份／安装与原生启动证据，不构建、签名、安装、退出、启动或执行 Git 写操作。

各任务不独占工作区，不回滚或覆盖其他成员改动。所有构建／测试子进程通过任务最小环境启动，禁止输出环境、凭据或调用 `xctest -help`；使用原生离屏测试和模拟数据，不触发 AWS 登录或数据查询。

## 验证与交付

1. 汇总单元测试验证数量、双向隔离、所属 SG 与行身份，保留重复项及未知字段。
2. 原生渲染验证两张汇总表、长字段、中英文／深浅色及窄宽布局；在真实实例详情测试中验证加载／失败仍保持原状态。
3. 统一严格构建、离线测试、资源词条与 Harness task 门禁，复核必要截图后提交。
4. 固定源码快照打包，构建前后哈希一致；验证架构、最低 macOS、双语资源、严格签名和 ZIP／App 一致性。
5. 正常退出旧进程，完整备份当前安装；同卷重命名和失败恢复保护更新本机并打开，验证 Bundle 版本、完成启动、持续运行与可见窗口，独立核验后记录交付。
