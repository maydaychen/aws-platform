# AWS Platform 0.4.2 发布记录

## 范围

按用户授权，将当前脱敏仓库重新公开至 `maydaychen/aws-platform`，发布 `0.4.2 (26)`。使用当前独立 Git 历史、公开昵称与 `noreply`，不恢复已删除的旧历史或旧附件。应用功能与本机已验收的 `0.4.1 (25)` 保持一致；本轮仅同步发布默认版本、文档、安装包和签名更新清单，不替换本机应用或查询真实 AWS。

## 发布顺序

1. 复核全部可达 Git 对象、提交身份、截图、外置私有扫描配置和公开资源。82 项打包测试与项目 release 门禁通过后，提交并冻结打包源码。
2. 保留现有 Bundle ID、Ed25519 公钥和两架构 Feed 地址；Apple Silicon 与 Intel 分别全新构建，执行 App／ZIP／DMG 隐私检查、Developer ID 签名、Apple 公证、票据和 Gatekeeper 验证。Developer ID 证书身份属于公开签名信息；用户已明确接受按现有签名发布。
3. 独立核验两个架构的版本、最低系统、许可、双语资源、签名、App／ZIP／只读 DMG 一致性；ARM 在隔离 AWS 配置与偏好下完成启动检查。
4. 重建公开仓库并推送当前 main；固定标签指向实际打包源，创建草稿 Release，上传两套 ZIP／DMG 与统一 SHA256SUMS。核对附件后公开为 Latest，匿名下载全部附件核验哈希和字节数。
5. 按既有生成器验证公开附件后生成候选 Feed；本次仓库重建仅保留新 `26` 条目，删除引用已失效旧附件的 `18/17/9` 条目，再以同一密钥重新签名并独立公钥验签。旧 XML 保留在当前 Git 历史中。
6. 更新双语下载入口、发布状态与两份 Feed，推送并回读实际 HTTPS 地址，核对签名、版本、附件绑定及远端 main。

## 职责与证据

主 Agent 负责提交、仓库创建、打包、签名／公证、上传、公开 Release 及 Feed 发布。release-verifier 仅独立核验并记录证据，不执行外部变更。过程证据位于 `.tmp/github-republish/`，正式产物位于 `dist/AWSPlatform-0.4.2-{arm64,x86_64}/`；本机私有扫描词继续只存放于项目外。
