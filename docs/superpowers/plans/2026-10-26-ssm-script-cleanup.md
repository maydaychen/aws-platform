# SSM 交接脚本清理

非规范性实施记录。范围仅为用户确认的 SSM 脚本残留修复，不包含其他重构、发布或本机安装。

## 目标与边界

`open()` 返回成功不能证明 `.command` 已执行；原脚本只靠退出 trap 清理，关联到编辑器或异常结束时可能留下定位元数据。补齐未执行脚本的回收，不改变显式 Profile、同组凭据验证、CLI／插件版本门禁或外部终端会话管理。

- 自有目录采用 UUID 名称、专用版本标记及私有权限；清理校验当前用户、文件类型、链接数和目录绑定，不跟随符号链接，不删除未知文件或无标记旧目录。
- 默认仅清理超过 24 小时的未执行脚本。启动与后续连接时触发有界后台扫描，扫描失败保持原文件；不保证到期立即运行清理。
- 扫描每批最多读取 4,096 个目录项，单次异步调用最多 16 批，批次间让出执行权；按根目录设备／inode 保存扫描游标，避免临时目录前部的无关文件让后部脚本长期无法被发现。游标仅持有一个目录流，遇根目录变化、读完或错误时关闭。
- 使用 macOS 13 已提供的 `lockf` 文件加命令模式协调脚本启动与清理；保留锁文件，不创建丢失的锁文件，不等待活动锁。
- Bash 已打开脚本并取得启动锁后，在导出凭据或发起 AWS 调用前删除一次性脚本与标记。退出清理保持幂等，不改变原有退出码；已建立会话不依赖临时文件。
- `lockf` 父进程持锁不能覆盖父进程被单独终止后的全部子进程寿命，因此不依赖它保护已建立会话。macOS 13 没有新版 FD-only 模式，不增加解释器或原生辅助程序。

兼容性依据为 Apple 的 [macOS 13 lockf 源码](https://github.com/apple-oss-distributions/shell_cmds/blob/058de24aa8c1469f1ca2853e31637d7ed3c29dff/lockf/lockf.c) 。

## 验收

1. 成功交接但从未执行的过期脚本可回收；未过期和持锁脚本保留。
2. 正常、失败及 TERM 路径不留一次性文件且退出码不变；长脚本自删后继续执行，仅终止锁包装进程不影响已开始的本地假会话。
3. 异常退出后无活动锁的过期项可回收；伪标记、未知文件、无标记旧格式、符号链接、硬链接、权限异常和替换竞争保持保守行为。
4. 所有测试使用临时文件、假 CLI／插件；不执行真实 SSM、读取实际 AWS 配置或产生云端写入。
5. 定向回归、必要构建及完整离线回归、静态门禁和独立关键路径复核通过后提交。
